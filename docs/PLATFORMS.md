# 跨平台使用：Hermes、ChatGPT 与 WorkBuddy

**定位：通用归档流程，Hermes 已验证。** 图文顺序、图片有效性、评论归属、时间精度和验收规则可以复用；平台工具名、权限、登录会话与文件输出不能直接照搬。

本页根据各平台官方文档说明可尝试的使用方式。**文档核实不等于本项目实测**：目前没有在 ChatGPT 或 WorkBuddy 完成 QQ 空间归档的端到端测试，也没有交付专门适配这两者的原生技能包。

## 选哪条路线

| 平台 / 模式 | 本项目使用方式 | 浏览器与文件边界 | 验证状态 |
| --- | --- | --- | --- |
| Hermes | 安装 `qzone-archive`，执行原有流程 | 需要可用的浏览器、文件工具和已授权 Vault | macOS 真实案例验证；安装脚本测试通过 |
| ChatGPT 普通 Chat | 提供归档规则和少量已导出的内容，让它整理 | 不能把上传文档当作获得本地 Vault 或 QQ 登录权限 | 提供操作建议，未实测 QQ 全流程 |
| ChatGPT Work（云端） | 提供规则，先测试少量网页采集与可下载输出 | 云端浏览器有独立会话；不是本机 Chrome，不自动写入本地 Vault | 官方有浏览器能力；QQ 网站兼容性未实测 |
| ChatGPT Work（桌面本地） | 按账号可用能力授权本地文件与应用，再做小样本测试 | 权限、可用工具和上线范围以当前账号为准 | 本项目未实测 |
| WorkBuddy | 通过官方“创建技能”入口建立平台适配流程，先验证少量样本 | 需核对浏览器/屏幕操作、文件读写与实际权限 | 官方有技能入口；本项目未实测 |

> 将 `SKILL.md` 交给另一个平台，不会凭空增加浏览器、文件写入或凭据工具。遇到能力缺失必须停止该步骤并明确说明，不要把生成一段 Markdown 当成整站归档成功。

## 一、Hermes：已验证路线

按 [安装指南](INSTALL.md) 将 `qzone-archive` 文件夹安装到当前 profile 的 `skills` 目录，新开会话加载技能；使用 [归档与验收指南](USAGE.md)。仓库里的 `scripts/install.py` 只为 Hermes 复制技能文件。

其他平台**不要运行这个安装脚本并以为已安装到自己的技能系统**，也不要修改 Hermes 的配置来适配它们。

## 二、ChatGPT 普通 Chat：整理已提供的资料

适合你已拥有少量文本、导出 HTML、JSON 或附件，希望整理为 Obsidian 笔记的情况，不是自动登录 QQ 空间的承诺。

1. 从本仓库下载 `qzone-archive/SKILL.md`，作为参考规则提供给 ChatGPT。若当前界面不接受该文件类型，复制相关规则到聊天即可；这是提供上下文，不是安装原生 Skill。
2. 检查 ChatGPT 的数据控制设置，选择可以上传的内容。先提供一篇不敏感文章，不上传完整私人归档、密码、验证码、Cookie 或浏览器配置。
3. 另外提供原始正文、评论层级和对应附件。只有截图时，提醒模型无法保证精确评论层级、原时间和图片原文件。
4. 使用下方示例。若当前会话能生成可下载文件，要求输出 Markdown、附件和核验清单；否则只接受文本草稿，明确尚未生成离线归档。
5. 下载输出后，由你解压并复制到本地 Vault，在 Obsidian 阅读视图检查图片与折叠评论。只得到 Markdown 文本、不具备附件时，不能标为离线图片已完成。

```text
参考我提供的 QQ 空间归档规则，整理我上传的这一篇样本。
只使用已提供的数据，不自行补充作者、时间、回复或图片。
保留原始图文顺序，将主评论与楼内回复分开，评论默认折叠。
如果当前工具能生成文件，请提供可下载的 Markdown、实际附件和核验清单；
否则给出 Markdown 草稿，并明确尚未生成文件、尚未完成图片离线保存。
没有附件或回复归属信息的项目列为待补充，不要编造。
本次只处理这个样本，不连接我的 QQ 账号，不发布任何内容。
```

**隐私提醒：** 把私密笔记上传到聊天与只在本机归档不是同一回事。上传前审查内容，并根据自身要求查看数据控制和所在工作区政策。

## 三、ChatGPT Work：具备执行工具时的小样本尝试

当前 OpenAI 官方文档区分 Chat 与 Work；旧的 ChatGPT agent 页面已指向 Work。以当前界面的功能和账号权限为准，不依据旧教程寻找已经变化的入口。

### 云端 Work

1. 若账号可用，打开 Work，提供归档规则及你自己的目标空间地址。
2. 要求它先说明实际可用的浏览器、HTML/DOM 读取、文件生成与附件下载能力，再处理一篇普通日志。
3. 网站访问需要授权时，检查地址。登录只在官方安全登录界面或接管浏览器过程中完成，不把凭据发进聊天。
4. 云端浏览器不共享本机已有登录；QQ 登录、扫码、网站访问或页面解析可能失败。遇到限制请停止并报告，不导出 Cookie 来绕过。
5. 明确要求先交付可下载样本和核验结果。云端输出需要你下载到本机后再导入 Vault，不能宣称已写入你的本地 Obsidian。

### 桌面本地 Work

官方文档说明，符合账号与工作区权限时可以使用本地文件和桌面应用。先核实当前会话的实际能力，仅授权指定工作目录与目标 Vault；不要默认所有账号都有此能力。网页登录与文件权限分别核对。

```text
请把提供的归档规则作为工作要求，而不是假设你拥有 Hermes 的工具。
先说明你目前可用的浏览器、页面读取、附件下载和文件输出能力。
本次只尝试我自己的 QQ 空间的一篇普通日志；登录由我在安全界面完成。
不得编辑、删除、点赞、发布或分享，不扩大到其他类别。
保留图文顺序，分离主评论和楼内回复，不补造时间。
输出样本、图片下载/跳过清单和原页对照结果，说明尚未完成的部分。
云端运行时生成可下载文件，不声称已写入本机 Vault；
只有明确拥有本地写入权限时，才在我授权的目录生成新文件。
遇到网站限制、无法读取 DOM 或缺少附件时，停止相应步骤并报告。
```

**不要误解 Codex：** 官方将 Codex 定位于代码与技术工作。它可帮助实现或检查归档代码，但本页不提供已验证的 Codex QQ 采集方案，也不把拥有终端等同于拥有可用的登录浏览器。

## 四、WorkBuddy：创建适配流程，再验证工具

官方指南提供“技能 → 添加技能”入口，包括“上传技能”“查找技能”“创建技能”。本项目推荐先用**创建技能**做适配，而不是假设原 Hermes 包可以无修改运行。

1. 在 WorkBuddy 打开技能板块，点击“添加技能 → 创建技能”。若你的版本界面不同，以当前官方指南为准。
2. 将下方要求提供给创建流程，并以本仓库 `qzone-archive/SKILL.md` 为规则参考。要求它使用自身实际工具重写步骤。
3. 特别移除对 Hermes 专有 `browser_exec`、`read_file`、`skill_view`、vault 工具以及 Hermes 管理 Chrome 的依赖。换成平台确实具备的对应能力；没有对应能力的步骤必须列为不可执行。
4. 检查生成技能、脚本、权限与数据外发范围，只授权专用工作目录、需要访问的网站和指定 Vault。
5. 先在新目录处理一篇普通日志，检查正文图文顺序、主评论/回复、附件与统计，再决定是否扩大范围。不要先对现有归档做批量覆盖。
6. 如果使用“上传技能”，先准备**符合 WorkBuddy 当前要求的技能包**并审核。官方确认有上传入口，但本项目尚未验证包格式、原包导入和运行，因此不承诺上传本仓库 ZIP 即可用，也不编造技能目录路径或配置字段。

```text
创建一个“QQ 空间归档到 Obsidian”的工作流程技能。
参考我提供的归档规则，但使用你真实具备的工具，不调用 Hermes 专有工具。
先说明是否能操作登录浏览器、读取正文 HTML/DOM、下载并验证图片、
执行文件处理，以及写入我授权的工作目录和 Vault。
缺少任何能力就标明需要人工完成，不声称可以自动执行。
只归档我合法可访问且明确授权的日志、说说和留言板。
逐批保存数据，按 ID 去重，核验来源条数，保留原时间精度。
图片按原位置保存到本地；下载失败和占位图需记录并跳过。
主评论与楼内回复独立提取，保留真实归属，评论默认折叠。
不索取聊天中的密码、验证码或 Cookie，不点赞、编辑、删除或发布。
首次只处理一篇不敏感日志到新目录，经过我检查后才扩大范围。
```

## 五、任何平台都需要的验收

- 来源记录与实际输出能够逐项对照，不能只报“完成”。
- 评论与楼内回复的作者、时间和归属有原始依据。
- 图片文件真实存在、可解码，引用正确，失效图没有混入。
- 日期精度不足没有被补造；隐藏、未展开或未采集的内容有披露。
- 云端生成、手动下载与写入本地 Vault 分别说明。
- 未经授权不扩大采集、不覆盖旧归档、不上传私人内容到仓库。
