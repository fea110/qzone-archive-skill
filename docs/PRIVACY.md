# 隐私与发布审核

## 技能与归档分开

本仓库只分发技能规则、说明文档、安装脚本和经过脱敏的局部效果图。用户生成的 Markdown、原始 JSON、附件、索引和下载清单必须留在个人归档，不加入本仓库。

原始数据可能包含仅本人可见内容、作者昵称、来源 QQ 号码、时间、回复与照片。QQ 原页的访问权限不会自动保护本地文件；本地归档默认没有加密，Obsidian 同步也可能把它传到云端。

## 登录与凭据

不要提交或通过聊天提供密码、验证码、Cookie、Token、浏览器配置、登录数据库、`.env` 或 `auth.json`。本项目安装脚本不读取这些文件，不修改 Hermes 模型与账号配置。

不要为了下载失效图片调用未知代理、第三方账号或绕过权限。只归档用户合法可访问且明确授权的内容。

## 真实截图的处理

示例来自真实 QQ 空间页面与用户提供的 Obsidian 页面局部图。按照用户授权，保留经过检查、不含敏感信息的普通正文和回复；账号、昵称、日期、头像以不透明矩形遮盖，不使用容易辨认的弱模糊。正文如包含真实姓名、联系方式、具体工作、地点等个人信息，则额外遮盖或换用其他片段，不把整段普通文字一律遮掉。

- 不上传原始截图，不在 Git 历史保留它们。
- 图片重新编码为 RGB PNG，不保留原始截图元数据。
- 原文链接、文件名、Vault 名称和系统目录也属于审核范围。
- Obsidian 示例是历史展开状态，不能被误标为最新采集验证图。

## 从私有转公开前

- [ ] 仓库确为 Private，审核完毕前不修改可见性。
- [ ] 用户逐张检查 README 中的截图，必要时进一步裁切或移除。
- [ ] README 和文档没有私人号码、路径、敏感原文或作者资料；展示的普通内容经过用户授权与检查。
- [ ] 文件列表和 Git 历史都没有私人归档或原始截图。
- [ ] 扫描敏感字符串并人工确认结果；自动扫描不能保证发现所有个人信息。
- [ ] 用户明确允许公开后，才在 GitHub 设置中改变仓库可见性。

发现泄露时应立即停止发布、移除敏感资源并清理历史；删除最新文件不等于历史副本消失。发现凭据泄露还需撤销或轮换凭据。
