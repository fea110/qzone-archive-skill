# 使用与验收

## 1. 确认范围

告诉 Hermes：自己的空间地址、Vault 实际路径、需要日志/说说/留言板中的哪些类别、是否下载图片、是否包含账号有权限查看的私密内容。默认不扩展到日记、草稿、回收站、相册。

有旧归档时先备份，约定输出位置。使用 Obsidian skill 读取库内协作规则，不能凭空假设库的位置。

## 2. 完成登录

优先使用受支持的浏览器工具和已授权会话。出现登录页时，由用户自行扫码或使用 Hermes 的安全凭据 UI；不在聊天中索取密码、验证码或 Cookie。不自动清除浏览器配置。

工具超时与网页未加载是不同问题。若使用诊断性 CDP 回退，只连接明确识别的 Hermes 管理浏览器，不连接任意用户调试端口，不提取登录秘密。

## 3. 分页采集

日志、说说、留言板可能分别在 iframe 中。先验证真实选择器，再逐页读取。保存每批 JSON 后用程序按 ID 去重；页码变化但内容 ID 不变时停止重试，不能当成新页。

时间保留原始字符串和精度。作者、楼层、时间、正文、楼内回复各自保存。来源页面完整文本可以留在原始 JSON，但不重复塞进阅读正文。

## 4. 图片本地化

按原始 DOM 顺序对应图片与正文。下载后验证可解码，排除“暂停访问”等可解码占位图；按哈希去重；保留 GIF 原始字节。失效图片在原位留简短说明，在清单记录原因。

最终 Markdown 使用归档内的相对路径。不能只下载附件却继续保留在线图片嵌入。

## 5. 整理阅读排版

正文独立；评论与元信息使用默认收起的 Callout。主评论与楼内回复按原始归属嵌套，不能把“我”等作者标签拼进正文。表情缩小，正文大图限制宽度。在 Obsidian 阅读视图检查。

## 6. 验收清单

- [ ] 来源可见条数、实际采集条数和去重后的数量可对照。
- [ ] 每篇日志存在笔记，每个分组索引能够跳转。
- [ ] 图片相对引用全部存在，附件均可解码。
- [ ] 没有将失效占位图当成真实图片。
- [ ] 正文图文顺序与原页抽查一致。
- [ ] 评论作者、时间、正文与楼内回复归属能回到原页核对。
- [ ] 不能验证的类别、折叠回复、失效图片已明确记录。
- [ ] 日期精度不足处没有补造时间。
- [ ] Obsidian 实际显示没有 Vault not found 错误。
- [ ] 原始 JSON、归档清单与笔记已保留，本地隐私风险已告知。

> 系统发出打开请求不等于应用打开成功；HTTP 200 不等于下载到真图片；翻到最后一页也不等于记录完整。
