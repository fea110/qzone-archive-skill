# QQ 空间归档

将用户有权访问的 QQ 空间日志、说说、留言板整理为 Obsidian 本地归档，保留图文顺序、可预览附件和评论归属。此技能是浏览器与文件工具的执行流程，不是独立爬虫；不得伪造缺失记录或承诺像素级复刻。

## When to Use

- 用户明确授权将自己的 QQ 空间保存到 Obsidian。
- 需要离线图片、清晰排版、主评论与楼内回复分离、可核验数量。
- 不用于绕过空间访问限制、批量采集他人内容、发布私人归档或自动操作点赞/分享。

## Prerequisites

1. 确认实际 Vault 路径、归档范围、输出位置与是否包括可访问的私密内容；有旧笔记时先备份。
2. 库内写入前加载 `obsidian` skill 并读取协作规则；不可用时先确认可替代的 Vault 文件操作流程。
3. 使用 `browser_exec` 等受支持浏览器工具。登录由用户自行扫码或通过安全 vault 工具完成；不在聊天索取密码、验证码、Cookie 或 Token。
4. 图片下载校验需执行环境有 Pillow；先检查再使用，不把安装脚本视为采集程序。
5. macOS 上的实际流程经过验证；Windows/Linux 需要重新验证浏览器、权限和 Vault，不能声称已实测。

## Procedure

### 1. 连接和确认空间

先检查登录状态和空间主页身份。个人中心可能显示好友动态，不代表本人发文；通过可见导航进入“日志”“说说”“留言板”。保留原页可见性标签，告知本地文件未加密。不要擅自采集日记、草稿、回收站、相册、视频或音频。

若浏览器工具超时而 Hermes 管理的 Chrome 仍在运行，可在明确识别当前实例后从其 `DevToolsActivePort` 与 `/json/list` 诊断连接，使用仅绑定本机的 CDP 回退；不连接任意浏览器调试端口，不提取 Cookie 或登录数据库，不清除用户配置。不要把工具超时直接解释为网站登录失败。二维码过期时刷新并向用户展示新二维码。

**完成标准：** 空间身份、类别、权限、目标目录已核对；登录资料不进入输出。

### 2. 逐页采集并持久化

在实时 DOM 确认 iframe 与选择器，不把下面的经验当成永久 API：

| 类别 | 已知节点与核验点 |
| --- | --- |
| 日志 | 通常 `#tblog`；列表 `a[rel=blog-detail-link]` 带 `blogid`、URL、标题与 `title` 发布时间；正文 `#blogDetailDiv`、`#pubTime`、`#infoBlogCate` |
| 说说 | `.box.bgr3`、`.goDetail[title]`；`.bd` 正文、`.md img` 附件、`.mod_comment` 可见回复；检查 `.has_more_con` 截断 |
| 留言板 | 通常 `#tgb`；`[id^=commentContentDiv_]`，最近 `.main` 内的 `.floor`、`.username`、`.comment_wrap`；`.mode_post` 时间、`.privacy-txt` 可见性 |

同源 iframe 才读取 `contentDocument`。图像优先取真实 `data-src` 或浏览器解析后的 `img.src`。下一页按钮 ID 会变，用已确认的 `a[title=下一页]` 等语义定位。

每批立即用 `write_file` 或程序持久化 JSON，再用 Python 按记录 ID 去重和计数。页码显示改变但内容 ID 未变时不要保存为新页。留言板遇到停滞可以切换页面后重进；仅在实时对象确实存在时调用 `QZBlog.Util.PageIndexManager.goDirectPage(n)`，并等待内容 ID 真正改变。

保留原始正文 HTML、图片顺序、时间字符串、来源、可见回复和可见性。发布时间与编辑时间分别保存；日期不完整就保持不完整，不能从 ID 推断年份、时分秒或时区。

**完成标准：** 缓存逐批落盘；唯一 ID 数量与来源显示数量可对照；未访问或无法加载条目有说明。

### 3. 提取评论层级

不能把整页 `innerText` 拼成主评论正文。日志 `[name=commentItemDiv]` 通常包住一个主评论：`.user_info .username` 作者、`.floor` 楼层、`.tit .time` 时间、`.comment_info > table` 正文。

后代 `[id$=_contentBlock]` 与 `[id$=_poster_nickname]` 标识楼内回复。克隆 `.comments_content` 后移除作者链接和 `.comments_op`，保留余下 HTML 及 `<br>`；作者、时间单独保存。离开 DOM 的克隆节点 `innerText` 可能丢换行，优先转 HTML。

紧贴正文的“我”可能是作者标签，不是正文开头；必须核对原节点关系。每条回复挂在真实父主评论下；不能虚构回复作者、时间或归属。只核验实际显示的回复，不把未展开部分声称完整。

同样缺陷出现时应逐篇核验全部相关日志。说说和留言板具有各自结构，必须单独逐页验证，不能凭日志成功声称已全部修复。

**完成标准：** 主评论与回复 JSON 分离；作者/时间/正文独立；数量和归属可以回到原页核对；覆盖不足有披露。

### 4. 下载有效图片

下载后用 Pillow 验证实际可解码，不能仅凭 HTTP 200 或 MIME 类型判定成功。制作本地联系表并使用 `vision_analyze` 排除“图片暂停访问”等可解码占位图。按 SHA-256 去重，保存原始 GIF 字节保留动画。

原 HTML 的相对图片 URL 可能指向错误页面。按来源 DOM 的有序图片列表对应浏览器解析的真实 URL；转换时让图片留在原有文字位置，不把图片全部追加在文章末尾。

附件保存到归档内的 `附件/`，类别笔记使用 `../附件/<hash>.<ext>` 等正确相对引用。无法预览的图片跳过，在原位置留简短说明，清单保存失败原因。原始 JSON 不覆盖。

**完成标准：** 每个保存文件可解码且非失效占位图；每个本地嵌入能解析；没有残留远程图片嵌入；下载、去重、跳过记录完整。

### 5. 生成易读笔记

每篇日志一份笔记；说说和留言板可按年份组织卡片，并为每项保留来源、ID 与原始时间。正文与评论分开，完整页面快照留在原始 JSON，避免 UI 按钮、分页和重复正文进入阅读区。

评论用默认收起的 `> [!quote]- 评论`，元信息用 `> [!info]- 原文信息`；楼内回复使用嵌套 `> > [!note]- 楼内回复`。说说/留言可用 `> [!note]` 卡片。保留段落、换行、强调与图文顺序；按实际时间排序，不精确时间不猜测。

Obsidian 图片可用 `![说明|宽度](路径)` 限制正文大图，表情宽度可约 24px。在阅读视图验证 Callout 与图片，不能把源码视图截屏当最终渲染验收。

**完成标准：** 索引可跳转；正文无重复整页快照；评论默认折叠且归属明确；图文顺序抽查一致。

### 6. 最终核验与报告

用程序复查去重数量、生成笔记数量、附件可解码状态、本地引用路径和未完成项目。用 `read_file`、`search_files`、`vision_analyze` 与应用实际显示确认，而非脑算或只看命令返回值。

Obsidian 深链接用明确的 Vault 标识与 Vault 相对路径。空格编码为 `%20`，不要用 `+`：`urllib.parse.urlencode(params, quote_via=urllib.parse.quote)`。系统打开命令退出零只证明请求发出，不能证明 Vault 已正确打开。

**完成标准：** 用户得到入口、真实统计、跳过原因、未核验类别与隐私提示；未完成部分不声称完成。

## Pitfalls

- 翻页成功不等于内容更新，必须比较 ID。
- 日期精度不足不能自动补造。
- 在线图片链接不等于离线备份。
- 可解码占位图不是原图。
- 日志的回复解析成功不能证明说说/留言完整。
- 原页权限不会加密本地文件。
- 浏览器调用成功、系统打开请求成功都不等于最终效果成功。
- 抽取过程中不点击编辑、删除、发布、分享、点赞等写操作。

## Verification

- 来源可见条数与唯一 ID 数量经程序核对。
- 每篇/每组 Markdown 与索引可访问，原始 JSON 与清单存在。
- 附件与所有引用有效，失效图没有混入。
- 图文顺序、评论正文与回复归属经原页抽查，覆盖不足已明确。
- Vault 实际显示和折叠阅读确认，无虚构时间、作者或缺失内容。
- 输出只到授权 Vault/工作目录，不自动上传 GitHub 或其他云服务。
